二级路由遍历
==================================

基础
--------------------------------
+ 请求在服务器端被两次或多次不同层级的路由或程序处理。比如，一个前端网关（BFF）先接收请求，然后再转发给后端的某个微服务。

漏洞成因
--------------------------------
+ 外层的程序可能对输入做了初步检查（比如只允许数字ID），但它把这个“看似安全”的输入，原封不动地拼接到内部请求的URL路径中，发给了第二个程序。而第二个程序（内部的API）却把这个拼接后的字符串当作了完整的、可信的路径去解析和执行。
+ 如： ``?packageId=../../../../API/system/users/search%3fpagesize=10`` 后端会进行=> ``/API/system/users/search?pagesize=10``

识别目标
--------------------------------
+ 架构特征：微服务架构、使用API网关（BFF）或.NET MVC/Core混合部署的应用。
+ 功能特征：任何无需复杂认证就能访问的公开功能点，特别是那些看似只接受一个ID或简单参数的接口。
+ 参数特征：URL路径中的参数（如 /api/resource/{id}）或查询参数（?file=xxx），这些参数最终可能会被用于构造后端请求。

测试方法
--------------------------------

注入控制字符，探测后端行为
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
+ 首先，在参数中插入 ``#、?、/`` 等有特殊含义的字符。
+ 插入 **?** ：如果参数被拼接到路径中，? 之后的内容可能被后端解析为查询参数（Query String）。
+ 插入 **#** ：# 在URL中代表锚点（Fragment），其后的内容通常不会被发送到服务器。如果应用逻辑因此发生变化，说明你的输入正在被用于构建后端请求。
+ 插入 **/** ：这可能会打破原有的路径结构，暴露后端的路径信息或触发不同的错误。

注入随机内容，触发内部错误
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
如果第一步没有明显反馈，可以尝试注入随机字符串（如 aaa）或特殊字符组合。目标是触发内部API的错误，从错误信息中“套”出后端API的地址、请求方法等敏感信息。这些信息是后续构造精准Payload的关键。

注入路径遍历Payload，尝试访问敏感API
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
+ 经典Payload： ``../../../../api/admin/users``
+ URL编码绕过：如果系统过滤了 ``../`` ，可以尝试URL编码 ``%2e%2e%2f``
+ 双重编码： ``%252e%252e%252f``
+ 绝对路径：有时直接使用 ``/api/admin/users`` 也能生效。
+ 注入查询参数：注意在Payload中注入查询参数，如 ``search%3fpagesize=10`` （%3f 是 ? 的URL编码）。

观察响应，验证漏洞
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
+ 状态码变化：从 403 或 404 变为 200 OK，是成功的强烈信号。
+ 响应内容变化：返回了预期外的数据，如JSON格式的用户列表、系统配置等。
+ 错误信息：有时错误信息本身就会泄露内部路径或API结构。
